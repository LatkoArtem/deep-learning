# Лабораторна робота 1

Ручний backpropagation для мережі `4 -> 8 -> 3` на Iris у `float64`.

```powershell
uv sync
uv run python backprop.py
uv run python backprop.py --wrong-gradient
```

Перша команда запускає правильну реалізацію, друга - дослід без ділення градієнта за логітами на кількість об'єктів. Результати збережені у `results.json` і `wrong_gradient_results.json`.

Для покрокового показу є `lab1.ipynb`. Відкрий його з цієї теки командою:

```powershell
uv run --with jupyter --with ipykernel jupyter notebook
```

## Дані та модель

`load_iris()` містить 150 об'єктів. Для кожного класу генератором `default_rng(0)` перемішуються індекси: 35 об'єктів ідуть у train, 15 - у test. Середнє та стандартне відхилення (`ddof=0`) обчислюються тільки на train.

Мережа:

```text
X (105, 4) -> z1 (105, 8) -> ReLU -> z2 (105, 3)
```

`W1` має форму `(4, 8)` і He-ініціалізацію `N(0, sqrt(2/4))`. `W2` має форму `(8, 3)` і Xavier-ініціалізацію `N(0, sqrt(2/(8+3)))`. Вектори `b1` і `b2` нульові.

## Формули

```text
z1 = X W1 + b1
a1 = ReLU(z1)
z2 = a1 W2 + b2
log p = log_softmax(z2)
L = -mean(log p[i, y[i]])

dz2 = (softmax(z2) - one_hot(y)) / 105
dW2 = a1.T @ dz2       db2 = sum(dz2, axis=0)
dz1 = (dz2 @ W2.T) * (z1 > 0)
dW1 = X.T @ dz1        db1 = sum(dz1, axis=0)
```

Проміжні масиви `z1`, `a1`, `z2` і `log p` зберігаються у `Cache` для зворотного проходу. NumPy-реалізація не використовує autograd.

## Звірка

| Величина | Значення |
|---|---:|
| Loss NumPy | 1.4562007801142816 |
| Loss PyTorch | 1.4562007801142818 |
| Різниця loss | 2.22e-16 |

| Градієнт | Максимальна абсолютна різниця |
|---|---:|
| W1 | 2.78e-17 |
| b1 | 3.99e-17 |
| W2 | 5.55e-17 |
| b2 | 1.39e-16 |

Усі значення скінченні, перевірка з PyTorch проходить за критерієм `1e-12`.

## Чисельна похідна

Для `W1[0,0]`, `b1[0]`, `W2[0,0]`, `b2[0]` використано `epsilon=1e-6` і формулу `(L+ - L-) / (2 * epsilon)`. Максимальна абсолютна різниця дорівнює `1.46e-10`, усі чотири перевірки проходять за критерієм `1e-7`.

## Навмисна помилка

Прогноз: loss не зміниться, але всі ненульові градієнти збільшаться у 105 разів. PyTorch-звірка та чисельна перевірка мають виявити помилку.

Так і сталося: звірка з PyTorch не пройшла, а всі чотири чисельні перевірки не пройшли. Loss залишився `1.4562007801142816`, бо формула втрат не змінювалася.
