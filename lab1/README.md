# Лабораторна робота 1

Ручний backpropagation для мережі `4 -> 8 -> 3` на Iris у `float64`.

```powershell
uv sync
uv run python backprop.py
uv run python backprop.py --wrong-gradient
```

`uv sync` встановлює зафіксовані в `uv.lock` залежності. Запуск без прапорця виконує правильну реалізацію, а `--wrong-gradient` - дослід без ділення градієнта за логітами на кількість об'єктів. Результати збережені у `results.json` і `wrong_gradient_results.json`.

Для покрокового показу є `lab1.ipynb`. Відкрий його з цієї теки командою:

```powershell
uv run --with jupyter --with ipykernel jupyter notebook
```

## Дані та модель

`load_iris()` містить 150 об'єктів. Для кожного класу генератором `default_rng(0)` перемішуються індекси: 35 об'єктів ідуть у train, 15 - у test. Середнє та стандартне відхилення (`ddof=0`) обчислюються тільки на train.

`W1` має форму `(4, 8)` і He-ініціалізацію `N(0, sqrt(2/4))`. `W2` має форму `(8, 3)` і Xavier-ініціалізацію `N(0, sqrt(2/(8+3)))`. Вектори `b1` і `b2` нульові.

## Розмірності

| Масив | Форма |
|---|---:|
| `X` | `(105, 4)` |
| `W1`, `dW1` | `(4, 8)` |
| `b1`, `db1` | `(8,)` |
| `z1`, `a1`, `dz1` | `(105, 8)` |
| `W2`, `dW2` | `(8, 3)` |
| `b2`, `db2` | `(3,)` |
| `z2`, `log_probs`, `dz2` | `(105, 3)` |

## Формули

```text
z1 = X W1 + b1
a1 = ReLU(z1)
z2 = a1 W2 + b2
log_probs[i] = (z2[i] - m[i]) - log(sum(exp(z2[i] - m[i])))
where m[i] = max(z2[i])
L = -mean(log_probs[i, y[i]])

dz2 = (softmax(z2) - one_hot(y)) / 105
dW2 = a1.T @ dz2       db2 = sum(dz2, axis=0)
dz1 = (dz2 @ W2.T) * (z1 > 0)
dW1 = X.T @ dz1        db1 = sum(dz1, axis=0)
```

Проміжні `X`, `y`, `z1`, `a1`, `z2` і `log_probs` зберігаються у `Cache`; вони потрібні для обчислення градієнтів під час зворотного проходу. NumPy-реалізація не використовує autograd.

## Звірка

Значення втрат: NumPy `1.4562007801142816`, PyTorch `1.4562007801142818`.

| Величина | Максимальна абсолютна різниця NumPy / PyTorch | Перевірку пройдено |
|---|---:|:---:|
| Втрата | `2.22e-16` | Так |
| Градієнт `W1` | `2.78e-17` | Так |
| Градієнт `b1` | `3.99e-17` | Так |
| Градієнт `W2` | `5.55e-17` | Так |
| Градієнт `b2` | `1.39e-16` | Так |

Усі порівнювані значення скінченні; перевірка проходить за критерієм `1e-12`.

## Чисельна похідна

Для `W1[0,0]`, `b1[0]`, `W2[0,0]`, `b2[0]` використано `epsilon=1e-6` і формулу `(L+ - L-) / (2 * epsilon)`.

| Параметр | Градієнт `backward()` | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---:|---:|---:|:---:|
| `W1[0,0]` | `-0.0199201843306` | `-0.0199201843909` | `6.03e-11` | Так |
| `b1[0]` | `-0.0705661115844` | `-0.0705661116207` | `3.63e-11` | Так |
| `W2[0,0]` | `0.1352302086055` | `0.1352302086977` | `9.22e-11` | Так |
| `b2[0]` | `0.0855216448420` | `0.0855216449880` | `1.46e-10` | Так |

## Навмисна помилка

Прогноз: loss не зміниться, але всі ненульові градієнти збільшаться у 105 разів, бо з `dz2` зникає ділення на `N=105`. PyTorch-звірка та чисельна перевірка мають виявити помилку.

Так і сталося: loss залишився `1.4562007801142816`, звірка з PyTorch не пройшла, а всі чотири чисельні перевірки не пройшли. Для всіх чотирьох градієнтних масивів максимальна абсолютна різниця між помилковим градієнтом і `105 *` правильним градієнтом не перевищила `7.11e-15`. Після досліду стандартний запуск знову використовує правильний градієнт.
